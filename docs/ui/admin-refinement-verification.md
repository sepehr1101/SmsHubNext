# بازبینی ساده‌سازی ظاهر ادمین

تاریخ: ۲۰۲۶/۱۱/۰۱. جهت مورد تأیید: [admin-design.md](admin-design.md). حالت antislop: during، انتخاب صریح کاربر در همین گفتگو.

## محدوده و محیط

تغییر فقط در نمایش قاب مشترک، اندازه و فاصلهٔ کنترل‌ها، خلاصه‌ها، میان‌برها و حذف دو تیتر تکراری است. هیچ handler، پرس‌وجوی SQL، رویداد کنترل، route، migration یا وابستگی عوض نشده است. سایت عمومی خارج از کلاس `.admin-refined` است. ساخت نهایی و بازبینی مرورگر پس از آخرین تغییر ترتیب stylesheet انجام شدند.

برنامهٔ واقعی با پایگاه محلی مستقل `SmsHubNext_SearchReview_20261101` و دادهٔ ساختگی اجرا شد. تمام workerهای ارسال و دریافت غیرفعال بودند. هیچ پیامک ارسال و هیچ هزینهٔ واقعی ثبت نشد. این گزارش تأیید استقرار، سرویس واقعی یا سلامت کامل همهٔ قابلیت‌های قبلی ادمین نیست؛ ایرادهای رفتاری قبلی خارج از درخواست صرفاً نمایشی تغییر داده نشدند.

## شواهد تعاملی

| کنترل یا مسیر | نتیجهٔ مشاهده‌شده |
|---|---|
| منوی داشبورد ← ارسال‌ها | مقصد واقعی باز شد؛ جدول و خلاصهٔ ساختگی بارگذاری شدند. |
| جستجوی شناسهٔ فارسی ۴ | فقط دستهٔ ۴ نمایش یافت و خلاصه با فیلتر هماهنگ شد. |
| جستجوی شناسهٔ ناموجود | پیام صریح بدون نتیجه نمایش یافت؛ پاک‌کردن فیلتر جدول را برگرداند. |
| آیکن فیلتر | انتخاب وضعیت سمت سرور باز شد. |
| انتخاب ستون | ستون تلاش پنهان شد؛ با انتخاب دوباره برگشت. |
| اکسل ← صفحهٔ فعلی | فایل دانلود شد؛ وجود `xl/workbook.xml` در فایل تأیید شد. |
| منوی تنظیمات ← مشتریان | جدول مشتریان با همان داده‌ها باز شد. |
| افزودن مشتری | فرم موجود باز شد؛ Escape از ورودی فعال فرم را بست. ذخیره اجرا نشد. |
| افزودن گیرنده در پیش‌نویس | ردیف دوم اضافه شد و حذف همان ردیف آن را برداشت. |
| بازبینی فرم ارسال خالی | خطاهای شماره و متن کنار ورودی و در پیام فرم نمایش یافتند؛ ثبت نهایی اجرا نشد. |
| تب ارسال مجدد روزانه | پنل موجود باز شد و بازگشت به ارسال پیام جدید کار کرد؛ بررسی/ثبت روز اجرا نشد. |
| منوی موبایل | باز شد؛ انتخاب ارسال‌ها به مقصد رفت و منو بسته شد. |
| منوی حساب | اطلاعات من در منو ظاهر شد؛ Escape منو را بست. |
| خطاهای نرم‌افزار | عنوان صفحه یک بار نمایش یافت؛ دریافت خطاها دادهٔ ساختگی را خواند. |
| دیالوگ خطا | باز شد؛ انتهای Stack trace ساختگی موجود بود؛ Escape آن را بست. |
| تب‌های گزارش | دسته‌بندی و روند ماهانه جدول مربوط را نمایش دادند؛ تازه‌سازی گزارش عمل کرد. |

بازبینی دسکتاپ در اندازهٔ پیش‌فرض مرورگر، موبایل با عرض ۳۹۰ و تبلت با عرض ۸۲۰ انجام شد. ورودی‌های فرم در موبایل داخل صفحه بودند؛ `scrollWidth` سند از عرض viewport بیشتر نبود. خلاصه‌ها در عرض میانی و موبایل دو ستون و میان‌برها به‌ترتیب دو و یک ستون شدند. جدول‌های عریض اسکرول در محفظهٔ خود دارند، نه در کل صفحه. نمایش خطای فرم و حالت خالی جدول بررسی شد؛ حالت بارگذاری و خطای دریافت موجود از همان `FeatureNotice` استفاده می‌کنند و حذف نشده‌اند.
