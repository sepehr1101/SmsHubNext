# پایش پایگاه داده

مسیر: منوی مستقل «پایش پایگاه داده» در سایدبار، هم‌سطح تنظیمات (`/admin/settings/database`). صفحه ورودی با ۹ کارت و مسیر راهنمای پنل هماهنگ است. همه خواندن‌های کاربر از مرز احرازشده مدیریت عبور می‌کنند. نام جدول/ایندکس شناسه فنی است و تغییر داده نمی‌شود؛ مقادیر عددی در نمایش فارسی و در Excel عدد واقعی‌اند.

## امکانات

- نمای کلی: نام، نسخه/Edition، فضای فایل داده و لاگ، درصد مصرف لاگ و علت انتظار آزادسازی لاگ.
- جدول‌ها: تعداد تقریبی از metadata، نه COUNT کل جدول؛ فضای رزروشده داده/ایندکس خوشه‌ای و ایندکس‌های ثانویه جداست.
- رشد: یک نمونه در هر روز UTC هنگام اجرای برنامه؛ نمودار مجموع فضای رزروشده در ۳۰ روز اخیر. روز فاقد نمونه صفر نیست. نگهداری نمونه‌ها ۹۰ روز است.
- ایندکس‌ها: LIMITED فقط با کلیک کاربر، نه پایش مداوم یا هنگام بازشدن صفحه. شامل rowstore، سطح برگ و IN_ROW_DATA است. تراکم در LIMITED ناموجود است؛ SAMPLED فقط برای ایندکس/پارتیشن انتخاب‌شده اجرا می‌شود. روی ایندکس کوچک SAMPLED ممکن است به اسکن کامل تبدیل شود. هر دستور حداکثر ۱۵ ثانیه مهلت دارد. تغییر ایندکس انجام نمی‌شود.
- Statistics: تعداد سطر هنگام تهیه آمار، تعداد تغییرات و درصد نمونه‌برداری، همراه زمان آخرین به‌روزرسانی؛ نبود آمار صریح نمایش داده می‌شود.
- درخواست‌ها: نشست‌های فعال همین دیتابیس، زمان اجرا و انتظار و شناسه مسدودکننده؛ متن SQL نمایش داده نمی‌شود و KILL نداریم.
- Query Store: ۵۰ کوئری بر اساس معیار منتخب؛ بازه‌های هم‌پوشان با ۲۴ ساعت اخیر و فقط اجرای موفق. مدت متوسط وزن‌دهی‌شده، CPU کل و خواندن منطقی کل نمایش داده می‌شود. متن SQL و پارامترها برای جلوگیری از افشای اسرار نمایش داده نمی‌شوند. Query Store خودکار فعال یا تغییر داده نمی‌شود.
- عملیات ایندکس: فقط sys.index_resumable_operations، نه همه CREATE/ALTER INDEXها. درصد موجود از SQL خوانده می‌شود؛ زمان پایان تخمین زده نمی‌شود.
- تاریخچه: عملیات قابل ادامه‌ای که نمونه‌بردار دیده ثبت/به‌روزرسانی می‌شوند. نام جدول/ایندکس، اولین/آخرین مشاهده UTC، پیشرفت و مدت اجرای گزارش‌شده SQL حفظ می‌شوند. حذف عملیات از DMV به معنی پایان موفق تلقی نمی‌شود. صفحه زمان آخرین مشاهده را نشان می‌دهد و نه زمان پایان. عملیات میان دو نمونه ممکن است ثبت نشود. تا ۵۰۰ رکورد آخر نمایش و سوابق ۹۰ روز نگهداری می‌شوند.
- هشدار: لاگ >=۸۰٪، انسداد >=۱۰ ثانیه، اجرای >=۳۰ ثانیه، عملیات resumable متوقف و نمونه روزانه قدیمی‌تر از ۲۶ ساعت. این‌ها هشدارهای عملیاتی‌اند، نه سیاست ریبیلد خودکار. شکست نمونه‌بردار نیز در لاگ و اخطار صفحه نشان داده می‌شود.

## نمونه‌بردار و مجوزها

`DatabaseMonitoring:Enabled` به صورت پیش‌فرض true است. برای توقف جمع‌آوری پس‌زمینه false کنید؛ خواندن دستی صفحات همچنان فعال است. نمونه‌بردار در شروع و هر ۱۵ دقیقه کار می‌کند؛ فقط دو جدول عملیاتی مهاجرت 0037 را می‌نویسد. هیچ ایندکس کسب‌وکار، آمار، Query Store یا مجوز SQL را تغییر نمی‌دهد. نمونه روزانه با قفل تراکنشی در اجرای هم‌زمان چند میزبان تکرار نمی‌شود. پاکسازی ۹۰ روز مربوط به همین داده‌های پایش است.

در SQL Server 2019، پایش بعضی DMVها به VIEW DATABASE STATE / VIEW SERVER STATE نیاز دارد. SQL Server 2022+ برای بعضی نماها VIEW DATABASE PERFORMANCE STATE / VIEW SERVER PERFORMANCE STATE می‌خواهد؛ نماهای metadata/statistics ممکن است مجوز شیء هم بخواهند. مجوزها باید براساس نیاز همان نما و خطای SQL توسط مدیر SQL داده شوند. پنل نه کاربر را sysadmin می‌کند و نه GRANT اجرا می‌کند. نبود مجوز/اتصال، هشدار یا خطاست و وضعیت سالم جعلی تولید نمی‌کند.

تاریخ‌ها در ذخیره UTC و در پنل تهران/شمسی‌اند. تاریخ بدون ساعت snapshot، روز UTC است. زمان last_updated آمار از ساعت سرور با offset جاری به UTC تبدیل می‌شود؛ روی سرور دارای تغییر ساعت فصلی، تفسیر timestamp تاریخی ممکن است به تنظیم منطقه زمانی همان سرور نیاز داشته باشد. StartedAtServerTime تاریخچه کلید شناسایی زمان اصلی SQL است و به‌عنوان UTC نمایش داده نمی‌شود.


### بازبینی اجرای صفحه‌ها

مشاهده نشست‌ها و هشدارها پیش از خواندن DMV از نظر مجوز مشاهده سراسری بررسی می‌شود؛ نماهای محدودشده به نشست خود کاربر، وضعیت سالم یا فهرست خالی کاذب تولید نمی‌کنند. بررسی نمونه‌ای ایندکس با خروج از صفحه لغو می‌شود و شناسه پارتیشن هم پیش از اسکن اعتبارسنجی می‌شود. ستون پارتیشن در فهرست ایندکس‌ها نمایش داده می‌شود. رندر تمام ۹ صفحه با مرز احراز هویت و دیتابیس آزمایشی نیز در آزمون یکپارچه بررسی می‌شود.
